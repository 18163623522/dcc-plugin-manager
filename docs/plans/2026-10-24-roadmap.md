# Roadmap（2026-10-24 用户需求记录）

来源：用户口头需求。登记到此，后续按里程碑推进。

## M7 候选：自研软件安装识别（带版本）

**需求**：识别用户自己开发的桌面软件的安装情况，最好能识别版本号。

**技术方案要点**：

- 检测：注册表卸载键 `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*`
  （及 Wow6432Node / HKCU），读 `DisplayName` / `DisplayVersion` / `InstallLocation` /
  `Publisher` / `DisplayIcon`；按发布者白名单（或注册表登记的产物名清单）过滤出自研软件。
- 版本兜底：对InstallLocation 下的主 exe 读 VS_VERSIONINFO
  （Rust 侧可用 `windows-pe` 解析或 PowerShell `(Get-Item).VersionInfo`，倾向纯 Rust）。
- 与现有引擎检测（detect::ue / detect::houdini）并列一个 `detect::apps`，
  registry 的 `PluginKind` 需扩展第三态（如 `App`），或独立一份 apps.json。
- 安装/更新语义与插件不同：v1 只做「登记 + 版本比对 + 打开发布页/安装包目录」，
  不代跑安装器；v2 再考虑 Release 资产静默安装。

## M8 候选：浏览器插件管理

**需求**：浏览器扩展也要纳入管理（识别 + 版本）。

**技术方案要点**：

- 检测：Chrome / Edge / Brave 的 `User Data\<Profile>\Extensions\<ext-id>\<version>\manifest.json`
  （%LOCALAPPDATA% 与 %APPDATA% 两套根），Firefox `extensions.json`。
- 版本：直接读 `manifest.json` 的 `version` / `version_name` / `name`；
  开发者模式 unpacked 扩展记录在 Preferences 的 `extensions.settings`（path 指向源目录）。
- 自研扩展（Chrome Web Store 之外）可复用现有 GitHub 源流水线：Release 里放 zip →
  解压校验 manifest → 引导「加载已解压的扩展程序」或生成开发者模式注册表项
  （ExtensionInstallForcelist 仅企业策略适用，个人用 unpacked 引导即可）。
- 宿主概念扩展：`PluginKind` 增加 `BrowserExt`，引擎页列出检测到的浏览器 + profile。

## 依赖关系

两者都是「宿主 + 已装实例 + 版本比对」模型，与现有 detect/registry/update 架构同构；
建议先落 M7（复用 registry 语义改动小），浏览器插件随后。
